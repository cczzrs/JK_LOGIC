# 自定义 JK 节点网络的构造、优化与验证

## 从需求到网络与验证规格

1. 明确函数或状态转换：输入输出位宽、数值解释、当前状态与下一状态、有效输出事件、发送顺序、完成或停止条件。算术需求也可以依赖状态和反馈，不应预先限定为无状态无环结构。
2. 写独立 oracle。无符号乘法是 `A*B`，加法是 `A+B`；有符号补码、模 `2^width` 截断、饱和裁剪是不同规则。状态转换需对输入序列、当前状态、下一状态及输出事件建模，不能仅比较一次最终整数。
3. 按规格映射 Xi，设计 Q 节点的顺序 `ex`、引用、`initial_q` 和 Yi 映射。无状态结构可按依赖关系构造；有状态或反馈结构要明确每次如何启动、读取当前 q、写回及继续触发。编号影响同一次发布后的入队顺序，但不是“参数已到齐”的依据。
4. 同时检查数据依赖和事件活性。输出可能不依赖所有输入，却仍需按约定重新发布。要求所有输入齐后才发布、多个 Yi 一起有效或跨多次发送计算时，必须专门设计同步和有效性协议，不能从现成算术结果推断这些性质。
5. 选择匹配需求的实现和验证路径，区分以下三层能力。

| 层次 | 当前范围 | 使用边界 |
|---|---|---|
| skill 设计任务 | 算术、位级布尔逻辑、状态转换，以及相应的结构和事件优化 | 按需求设计网络及独立验证；不等于已有覆盖全部需求的编译器 |
| 现成 Builder / CLI | Builder 提供 `not/and/xor/or/mux/fullAdder/add` 等组合方法；CLI 支持双操作数 `mul/add/and/or/xor`，各 1..32 位、无符号、LSB-first；可追加有状态自反馈输出节点 | `finish` 固定采用双操作数 JSON 布局与完整输入排空协议；`verify.mjs` 只有这五种独立数学 oracle |
| 专门扩展 | 有符号、减法、比较、截断、饱和、其他端口或输出编码、通用状态转换及其他反馈或发送协议 | 补充生成逻辑、JSON 封装、oracle 和测试；不能只修改 `spec` 或套用已有通过报告 |

Builder 是节点和表达式构造工具，不会学习权重或自动搜索全局最优结构。`emit` 只接受以 `J0` 开头的无状态表达式；参数必须为 0/1、Xi 或已经生成的 Qi。`finish` 会拒绝与固定封装冲突的规格，不会通过修改元数据实现其他语义。它可以为另一个非空操作名称封装符合上述双操作数布局的输出，但未知操作不会因此获得 CLI 算法或独立验证 oracle。通用状态模型需要专用 JSON 封装，明确声明自己的 `initial_q` 和协议。

## 随附算术构造方法

`and/xor/or/not` 将数学布尔运算写成 [contract.md](contract.md) 中的顺序 `ex`，再通过引用连接节点。方法名中的 `fullAdder` 表示三位输入的求和辅助计算，产物仍是自定义 JK 节点网络。

### 乘法

无符号 `a_bits × b_bits` 的完整积为 `a_bits+b_bits` 位。为各输入位生成部分积 `p[i,j]=A[i] AND B[j]`，权重为 `2^(i+j)`。按权重分列；一列超过两项时，用 `fullAdder` 将三项压成同列的 sum 和下一列的 carry，直到各列最多两项；最后对剩下的两行进行一次逐位加法。构造必须保留完整结果所需的最高有效进位。

`fullAdder` 复用 `p=a XOR b`：`sum=p XOR c`，`carry=(a AND b) XOR (p AND c)`。进位的两项不能同时为 1，因此这里 XOR 等价于 OR；不能把这一结论推广到不互斥的项。两项求和则为 `sum=a XOR b`、`carry=a AND b`。最终输出的最高位只求和，不生成无用的额外进位。

8×8 示例包含 64 个部分积、16 个输出，最大值 `255×255=65025 (0xFE01)`。穷举 `256²=65,536` 个输入对包含零、一、最大值、单比特、最高位、交替位和进位链。完整输入域的通过结果仍只适用于报告中的初始状态和执行协议，不证明节点数最优。

### 加法与按位运算

- 加法：逐位组合求和与进位，完整输出宽度 `max(a_bits,b_bits)+1`。
- AND / OR / XOR：逐位应用对应节点构造，较短操作数在高位补零，输出宽度 `max(a_bits,b_bits)`。
- 选择辅助方法：`a XOR (s AND (a XOR b))`，s=0 返回 a，s=1 返回 b。Builder 已提供 `mux`，CLI 没有独立的 mux 命令或对应 oracle。

## 状态、反馈与专门扩展

状态可保存结果、复用中间值、累计、计数或协调输入；反馈可组织迭代。是否使用它们取决于节点数、执行次数、响应延迟和协议要求，不能因为任务是加法或乘法就排除。

最小的状态转换例子：`Q0.ex=K(X0)`，`initial_q={"0":[],"1":["Q0"]}`，`q_y=[{"Y0":"Q0"}]`。每次 X0 到达后，从当前 q 开始计算；X0=0 保持、X0=1 翻转，写回并向 Y0 发布。状态由 `initial_q` 和更新规则建立，这个例子无需自引用。单输入布局使用专用 JSON 封装，补全端口、统计和规格；独立验证可用条件分支 `x===1 ? 1-state : state`，比较连续输入的 q 与输出事件。

随附 `--stateful-output` 是已实现的一种形式：对每个无状态输出来源 P 新增 R，在 `initial_q["0"]` 中声明 R，令 `R.ex=K(R)K(P)`，Yi 映射到 R。R 执行从旧 q 开始，`K(R)` 此时读取同一个旧 q，先得到 `q XOR q=0`，再通过 `K(P)` 保存新结果。q 保持到下次执行。这是具有持久 q 的自反馈输出节点。

R 必须等无状态来源 P 到达才能入队；入队时 P 的槽已清空。R 随后向自身发布虽然产生事件，但 P 尚未再次到齐，所以不会独自再触发 R。每次 P 新发布又可激活 R，重复同值也会写回并发布。删除 `K(R)` 会改成“旧值 XOR 新值”；将 P 改成有状态来源会改变到齐集合，必须重新分析反馈行为。

其他反馈形式，例如反复复用求和网络完成移位累加，也在 skill 可设计的范围内，但目前 CLI 没有实现对应生成算法。应专门定义初值、启动、迭代次数、完成条件及 Xi / 无状态来源对反馈的触发约束。只依赖有状态来源、没有需到齐来源槽的节点，每次来源事件都能执行；这样的反馈区域即使数值不再变化，也可能持续发布而不停止。有限任务需要分析事件何时耗尽；持续任务需要定义观察窗口、有效输出及停止条件，不能一律用现成算术验证器的排空要求判错。

其他常见扩展的设计方向也需要独立实现和验证：

- 减法：约定借位、模运算或有符号结果，再构造补码加法等计算，不能擅自丢弃借位。
- 比较：从高位逐步判断相等与大小，明确输出编码。
- 有符号、截断和饱和：实现数值解释、符号扩展、结果选位或裁剪，同步修改端口和 oracle。
- 小型布尔函数：先得到布尔表达式或依赖图，再映射为节点的 J/K 序列；较大函数采用分块组合，避免直接枚举导致产物指数增长。
- 通用状态转换：按转换函数和事件协议构造，专门验证初始状态、重复事件、输入序列、状态更新和反馈行为。当前工具没有通用状态机编译器，也没有全状态等价证明器。

## 优化目标及顺序

首先保持规格要求的数值、状态转换和事件行为；然后按用户目标减少节点数、操作数量、依赖深度或运行中的执行次数。若用户指定来源数或操作数上限，应拆分表达式并重新验证真实统计和行为，不能只修改统计字段。

现成生成器在构造表达式时做常量折叠、对交换对称运算排序参数、共享完全相同的 `ex`；乘法使用上述列压缩；最终输出封装后从输出反向遍历，删除无用节点并连续重编号。`--no-opt` 关闭可选的布尔化简和相同表达式共享，但仍保留双常量直接计算、列压缩、最高输出位无用进位删除、输出封装及无用节点清理，不能称为“关闭所有优化”。

生成模型会记录实际节点数、来源和操作 token 的统计；验证运行会记录执行总数及队列峰值。依赖深度、fan-out、最大等待来源数尚未自动记录，用户需要这些指标时须明确计算方法并补充测量，不能声称现有报告已经包含它们。

**局部数值等价不等于事件等价。**

- `J0K(a)K(a)=0`，但删掉 a 会把依赖到达的重复执行改为仅初始化执行。
- `J0K(a)J0K(b)=b`，但删除 a 会缩小到齐集合，可能提前触发。
- 初始 q、状态写回、执行时读取有状态来源，以及无状态节点的外部缓存，不能用无状态局部真值表代替。
- 共享重复无状态计算可能在完整输入排空协议下保持最终值，但仍会改变节点身份、执行数与轨迹；不能直接推广到有状态来源或交错输入。

新设计应在声明的协议下优化并重新验证。优化已有状态网络时，至少比较有效输入对应的输出值、有效输出事件次数、最终 q、队列和缓存，以及下一次输入的行为；状态编码变更需要明确的状态对应关系。若要求全事件等价，还要约定并比较来源集、状态分类、触发次数和先后顺序。有限轨迹相同不等于已证明所有状态和所有事件交错都等价。

## 必做关卡一：小结构拼接复用前

每一种即将拼接或循环复用的小结构，必须先完成函数/状态转换、接口事件和最简性检查，包括加法与进位、选择器、同步屏障、有限控制、状态保存及初始化模板。先优化模板，再复制或接入网络；不能先大规模拼接，再仅凭整网输出正确跳过模板检查。

1. 记录模板的输入与输出、来源类型、初始状态、常量绑定、触发协议和优化目标。循环使用时验证重复同值输入、状态清理或保持方式，以及下一次调用能否再次触发。
2. 比较更少节点、更短 ex、较少运行操作的合法构造，先执行可证明安全且符合目标的改进。小真值空间可穷举表达式或小型拓扑；来源数/输出数下界也可证明限定范围内的最简性。节点数与操作量冲突时记录取舍，不能将单一指标较优称为全面最优。
3. 用独立 oracle 验证实际要拼接的模板。已验证的小结构证据可缓存，但缓存键必须包含模板内容、接口类型、初值、常量、位宽、优化目标和依赖前提；这些条件改变须重新核对。只写一份模板说明或事后检查它出现的次数，不等于执行了前置检查。
4. 记录已证明最简的范围、尚未排除的构造及所选方案。找到更简候选后必须验证并处理；搜索尚不完备时可以保留当前正确方案，但必须标明未证明最优，不能用“调用 Builder”代替结论。

## 必做关卡二：完整网络与全部 ex

完整网络组装、状态及输出封装后，必须再做整体检查。小结构分别最简，并不保证拼接后的网络最简：常量绑定、重复来源、表达式展开和同步组合都可能产生新的冗余。

**整体结构检查**至少覆盖：

- 所有节点的事件与数据可达性、无用输出或中间量；不能只按数值依赖删掉负责同步的引用或节点。
- 相同或等价子结构能否共享、可复用的运算是否仍有并行副本、内联后是否出现新的化简；有状态实例即使 ex 相同也不能直接合并。
- 状态位、输入选择、同步、控制和结果写回的总成本；局部减少运算节点但增加更多控制节点时应比较完整方案。
- 初始化、触发次数、读写顺序、帧或调用边界、反馈终止条件。改变共享、来源、状态编码或编号后，必须重新验证相应前提。

**全节点 ex 检查**必须实际遍历最终模型的全部节点，包含未经过 Builder 的手工模板。为每个节点登记 ID、状态/初值、唯一来源集合、需到齐集合、原表达式与操作数，并主动检查下列类别；这不是仅检查几个已知字符串的白名单。

| 类别 | 合法候选示例或检查方向 | 必须满足的条件 |
|---|---|---|
| 无效常量操作 | 删除 `J1`、`K0`，消去相邻两次 `K1` | 保留非空表达式及无状态节点开头的 `J0` |
| 重复与抵消 | 连续 AND 去重，连续 XOR 按奇偶化简 | 检查完整来源集合；`J0K(a)K(a)` 可改为 `J0J(a)`，不能直接丢掉 a |
| 被后续清零覆盖的计算 | `J0K(a)J0K(b)` 改为 `J0J(a)K(b)` | 数值相同并保留 a、b 的触发引用 |
| 自状态冗余 | 有状态 Q 的 `J0K(Q)A` 可改为 `J(Q)A`；若 A 已含 Q 引用，可进一步直接使用 A | Q 必须是当前节点自身；起始累加值与自引用读取同一个旧 q |
| 恒零/恒一发布 | `J0K(a)K(b)J0K1` 改为 `J0J(a)J(b)K1` | 每个原来源仍存在；不能改为只初始化一次的纯常量节点 |
| 选择与布尔因式 | 检查边界分支、吸收、反相与因式合并，重排连续同类运算 | 不得任意交换 J 与 K；保持独立输入下的函数或声明并证明约束 |
| 小表达式最短搜索 | 在允许的 J/K、常量和来源范围内搜索更短合法序列 | 搜索状态同时追踪函数和引用来源集合；仅找最短真值表达式可能删掉事件来源 |
| 初始化与可达状态 | 无来源、初值为 0 且只初始化执行一次的有状态 `J0K1` 可改为 `K1` | 证明单次执行与 reset 恢复，不能推广到会重复执行的节点 |
| 恒值信号与状态关系 | 利用运行时恒一脉冲、选择状态包含关系等进一步缩短 ex | 分别证明前提建立、每次执行保持、执行顺序及复位恢复；禁止将初值或抽样观察当作不变量 |

以上示例中的 a/b/Q/A 是说明符号，生成物必须换成合法来源或实际 token 序列。对于全模型候选，还应搜索规则组合产生的新机会；每次改写必须严格改善所选成本，避免反复来回替换。

### 证明与事件约束

无条件改写须覆盖全部独立来源和所需的执行前 q；自引用与旧 q 绑定为同一个变量。可采用穷举、布尔代数正规形或可核验求解证明。对于平坦 J/K 序列，可以在布尔环中表示 XOR 为加法、AND 为乘法，并用 `x*x=x` 归约比较多项式；这也能处理来源很多的屏障表达式。随机抽样不能代替这一步。

有条件改写须单独列出前提与证明。例如初始化后状态从 0 变为 1，不表示读取者总能读到 1；还须证明读取者不能在首次写回前执行。利用选择状态关系时，需要证明状态转移闭合及读取的是旧值还是新值。数值 ID 顺序若参与证明，必须作为结构验收条件固定下来。

局部改写默认保持节点 ID、状态分类、初值、完整唯一来源集合、需到齐集合和输出映射。改变来源或拓扑的候选转入独立结构优化验收；只有局部真值相等不能放行。需要比较哪些可观察事件必须明确：例如输出与节点执行等价，并不自动包含每条中间投递记录相同。

以下是必须拒绝的错误推理：有状态节点初值为 0 就删除任意 `J0`；把别的 Q 当作当前节点旧 q；把仅用于触发的来源当成无用变量删除；从重复测试中观察到信号恒一就直接常量传播；看到反馈值不再变化就认为不会再次发布。

### 审查闭环与交付记录

小结构优化后构建网络，整体改写后重新检查小结构前提和全部 ex；只要还有已证明安全且符合目标的改进就继续处理。停止条件是声明的规则和搜索范围不再产生可证改进，而不是节点数达到一个预先估计值。

优化审查报告独立保存并绑定最终模型 MD5、created_at 和文件摘要，至少包含：

- 小结构拼接前检查的模板、前提、实际验证、选择依据与最优性范围；整体结构候选、处理结果和未采用原因。
- 全部节点的审查结论，覆盖数等于最终节点数；改写前后 ex、规则与证明类型，或保留原因。可汇总相同理由，但不能遗漏节点。
- 节点数、状态位数、静态 token 总数及最大值、实际节点执行次数、实际 J/K 操作数和已测队列峰值；注明各项测试条件。
- 最终文件身份、使用的规则/搜索范围、仍未证明最优的部分。结构和 ex 修改后重新计算摘要与统计，旧报告不得绑定到新模型。

“已通过功能验证”“已完成所声明范围的优化”“限定词表/接口下最短”“全局最优”必须分别表述。小结构最短证明不能推广到网络整体，整体结构检查通过也不能代替全局下界证明。用户明确要求未优化基线时记录未应用原因，仍不得跳过正确性验收。随附通用 CLI 没有自动实现上述全部搜索，调用技能的助手需按当前模型补充检查与证据。

## 验证路径与报告边界

随附 `verify.mjs` 使用独立 BigInt 算术 oracle，并通过本目录的真实 FIFO 引擎执行模型；避免用 JavaScript 32 位整数拼接完整的大数输出。主验证从模型声明的初始状态开始，在一条连续轨迹上逐组发送完整输入，组间排空但不 reset。每轮检查各 Yi 恰好新发布一次、所有输出位正确、队列排空且到达缓存清空；然后连续两次发送最大值再发送零，检查同值事件和后续输入仍然有效。有状态和有环模型只要满足这份算术规格，也可以接受验证；声明标准 architecture 时还会检查是否符合其结构含义，自定义 architecture 需使用独立的非空描述。

无 `--samples` 时，工具只对总输入位数不超过 16 的模型穷举；超过时要求显式抽样。抽样会加入边界、单比特和确定性随机输入，并去重，报告中的实际样本数不一定等于命令参数。抽样结果必须标 `sampled`，不能写成穷举或形式证明。执行步数预算用于发现超出预算的重复或未完成执行；它不是终止定理，`queueLimit` 也只是发送门槛。

验证工作还应按需求分层：

- **局部表达式**：枚举来源值及所需的起始 q，检查 J/K 顺序和局部数学结果。`selftest.mjs` 包含基础公式和生成器回归检查，不能由此声称任意新表达式已经验证。
- **结构及封装**：校验语法、ID、引用、初始状态分类、端口、实际统计和散列；分析输出依赖及反馈触发。现成算术验证器拒绝纯常量来源节点，是重复算术协议的约束，不能解释为引擎或 skill 禁止纯常量节点。
- **函数与事件**：使用适合需求的 oracle，检查值、发布次数、终止或指定观察窗口。现成验证器只有五种双操作数 oracle，不支持任意状态转换。
- **状态与连续性**：通用状态需求另行比较下一状态、多个初始状态和输入序列。现成验证器只核对五种运算的算术输出、发布和有限输入轨迹；reset 检查恢复 `initial_q`，但没有通用 `next_state` oracle，不能证明自定义内部状态更新符合期望关系。报告中的有状态和自反馈节点计数，也不表示穷举了所有初始 q、输入顺序或反馈轨迹。状态需求应提供专门的状态验证器。
- **重置与重新解析**：主验证后，脚本 reset 并检查队列、缓存、输出及 q 恢复情况，运行 5 个边界输入；再把模型序列化为 JSON、重新解析并校验，用新引擎运行 5 个边界输入。报告分别记为 `reset_cases` 和 `reload_cases`。后一阶段不是独立的磁盘保存加载测试，也不是运行 checkpoint 续跑；一次连续遍历通过不意味着每个输入都从全新初始状态测过。
- **形式证明扩展**：若需要布尔等价证明，可另行建立规格与模型的 miter 并使用 SAT/SMT 等求解器；本工具没有实现这条证明路径。未找到反例不等于 UNSAT，布尔证明也不能代替状态、启动和事件终止分析。

验证报告独立于模型。成功报告记录模型散列、覆盖模式、位宽、覆盖数量、节点状态统计、执行次数、队列峰值及适用协议；执行次数包含主验证、重复输入、重置及重新解析阶段。API `verify` 失败时抛出异常，异常的 `error.report` 携带 `passed:false`、`phase`、`error`、已完成覆盖计数，以及可获得的首个 `counterexample`（输入 a/b、预期值、实际值和输出发布次数）；尚未进入执行时反例为 `null`，不能伪造运行结果。阶段包括校验、穷举或抽样、重复发送、reset 和 reload。失败报告中的 `model_md5` 只是输入模型声明的摘要值，尤其在摘要校验失败时，不能将其视为已通过校验的身份。

CLI 获得有效且可写的独立报告路径时会写出失败 JSON 并以非零状态退出；参数错误、读取失败也应报告其阶段。报告路径与模型为同一文件（包括软链接或硬链接）时禁止覆盖，只输出错误；报告路径本身不可写时也不能保证报告落盘。具体字段和错误阶段名称以随附脚本为准。

交付时区分构造事实、已运行验证、尚需实现的扩展及未测试边界；不能把抽样通过写成全面证明，也不能把设计方法写成已有功能。性能数据只代表所测模型、输入协议和运行环境。
