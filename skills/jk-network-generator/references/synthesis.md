# 构造、优化与验证

中央 JKRD 定义规则，本页说明本技能的构造策略与验收。先通过 `source.mjs` 读取现行主源，再核对 [实现接口](contract.md)。所有节点连接必须满足 V4；专题的旧模型不能直接视作可加载示例。

## 需求与模板边界

确定函数或状态转换、输入输出位宽、位序、符号、初值、溢出、发送次序和输出事件。独立 oracle 应直接使用数学或业务状态定义，避免再次用生成器的 J/K 分解计算“期望值”。例如乘法用 BigInt `a*b`；累计奇偶用独立状态翻转逻辑，并比较每个输出事件。

CLI 提供无符号 `mul/add/and/or/xor`，每个操作数 1..32 位、LSB-first、完整精度。有符号、减法、比较、截断、饱和、任意端口布局和通用状态转换，须另外实现生成逻辑与 oracle。不能只修改规格文件就获得新能力。

`Builder` 接受构造期 Xi、已经创建的 Qi 和数字 0/1，提供 `not/and/xor/or/mux/fullAdder/add`。`emit` 创建以 J0 开头的符号表达式；中间结构不代表可加载模型。`finish` 插入 V4 输入副本与无状态桥接，重映射普通计算的来源引用，清理无用节点并重新连续编号，最后交给严格快照构建器。

## 算术生成结构

- 输入副本 Q0..Q(N-1) 均有初始 q，EX 固定为 `J0K(Xi)`；后续 N 个桥接节点是无状态 `J0K(对应输入副本)`。
- 算术核心用桥接来源及其他无状态计算来源形成到达屏障。相同输入也会产生新的复制任务、桥接事件和计算任务。
- 完整输出宽度：乘法为 `a_bits+b_bits`，加法为 `max(a_bits,b_bits)+1`，按位逻辑为 `max(a_bits,b_bits)`，短操作数高位补零。
- 恒值结果必须保留合法触发来源。用零值前缀 `J0J(来源Q)`，必要时再 `K1`；不生成纯字面量节点。
- 声明但被数值化简移除的输入也需要被引用；生成器通过无状态屏障将这些桥接来源接入一个输出，不把内部节点加到 q_y。
- `--stateful-output` 为每个结果追加 `J0K(结果Q)` 的有状态节点，初始为 0。它等待无状态结果事件并保存最新 q，允许 EX 以 J0 开头。

乘法先形成逐位 AND 部分积，按权重分列；每列超过两项时，用 fullAdder 将三项压为同列 sum 和下一列 carry，再对剩余两行求和。fullAdder 使用 `p=a XOR b`、`sum=p XOR c`、`carry=(a AND b) XOR (p AND c)`；进位两项互斥才允许这里用 XOR 代替 OR。最高输出位不产生无用的额外进位。

`mux(s,a,b)=a XOR (s AND (a XOR b))`，s=0 取 a、s=1 取 b。Builder 有此方法，CLI 没有独立 mux 命令及 oracle。

## 状态与事件设计

状态由 initial_q 决定，不能凭 EX 以 J0 开头就认为无状态。有状态节点可显式读取自己的执行前 q，但自身发布没有自触发边。所有其他 Q 来源连接均参与 DAG 检查，传播条件不会豁免循环。

累计奇偶可以使用有状态输入副本 Q0 和有状态 `Q1.ex=K(Q0)`；无需自引用。按轮输入 1、1、0、1 时，Q1 从初值 0 依次变成 1、0、0、1。若两次输入在复制前到达，两次复制均读取最新 Xi；这与逐项历史输入不同，须按用户协议验证。

直接读取多个有状态来源的普通节点会因每个来源事件独立入队。要求数据汇合时使用无状态桥接形成屏障；需要保存每次业务输入或结果时，不能把待执行任务数量当作历史存储容量。动态等待区按中央专题另行设计，现有静态模板不提供创建/释放节点机制。

`changed/rising/falling` 等是需要组合结构实现的条件，不是合法 pro 值。输出绑定只能连接 q=0/1 节点；内部过滤应通过结构控制数据节点的求值，并核对是否有其他来源绕过许可独立触发。

## 优化的三个检查阶段

**复用前检查小结构。** 对基础运算、选择、输入桥接、触发恒值、控制和状态模板，确定来源类型与执行前提，检查完整真值及事件行为，比较更少节点或更短 EX 的候选。现成 Builder 的模板不是最简证明。纯数值真值只证明表达式结果，不证明屏障、传播及状态行为。

**生成后检查整体。** 检查共享、无用结构、内联、常量传播、状态和同步开销。重连或删除来源可能改变触发次数、读取时机或并列入队顺序；不能只比较最终整数。输入副本不得删除或改写 EX，剩余全部节点仍须满足引用、被引用、DAG 和输出绑定要求。

**逐节点检查最终 EX。** 遍历全部节点，包含输入、桥接、手工控制和状态节点。记录每个节点的 ID、分类/初值、来源集合、无状态屏障集合、pro、原 EX、候选、证明和改写或保留结论。节点变动后重新核对，覆盖数须等于最终节点数。

| 检查方向 | 候选或处理 | 约束 |
|---|---|---|
| 恒等操作 | 删除 J1、K0 或相邻偶数次 K1 | 保持非空、合法来源和无状态首个 J0；输入副本固定 EX 不变 |
| 重复/抵消 | `J0K(a)K(a)` 可比较 `J0J(a)` | 保留来源 a 及完整真值 |
| 清零前冗余 | `J0K(a)J0K(b)` 可比较 `J0J(a)K(b)` | a、b 都保留；先核对分类和触发 |
| 自身状态 | 使用“起始 q 与自引用读取同一个旧 q”证明 | 不能把其他 Q 当旧 q，不能加入自身事件边 |
| 恒值结果 | `J0J(a)J(b)K1` 保留 a、b 的触发关系 | 不能化为被禁止的纯常量节点 |
| 布尔因式/MUX | 比较边界、吸收、互斥和反相 | J/K 通常不能任意交换，协议前提须明示 |
| 有限最短搜索 | 枚举合法操作序列 | 同时追踪函数、来源集合、分类与 pro；到达搜索限制报告未完成 |

示例中的 a/b 必须换成合法 Q 引用；它们不是可直接写入 JSON 的参数名。

无条件局部改写覆盖全部独立参数及需要的旧 q；自引用与旧 q 绑定为同一个变量。可用真值穷举、布尔代数或可核验求解证明。有条件改写须证明前提如何建立、每次执行如何保持、复位/恢复后是否仍成立；不能以初值或抽样观察替代不变量。

优化后核对输出事件序列、状态序列、任务生成与执行数、队列归属、队内顺序、优先级、任务锁存数据、执行时实际参数、传播次数与未收齐集合。数值等价不表示任意重连或交错发送都等价。

`--no-opt` 关闭可选布尔化简与完全相同 EX 的共享，仍保留必要 V4 封装、双常量直接计算、乘法列压缩及无用节点清理。用户要求基线时记录未应用的候选，不强制替换其目标。默认生成器没有自动实现全部逐节点审查、通用最短搜索或全局最优证明；实际调用技能构造新模型时须补充相关证据。

## 验证及报告

`validate.mjs` 校验任意完整 V4 快照，包括非空 FIFOS，不证明目标函数。`verify.mjs` 另要求独立算术规格与空初始队列，然后在一条持续运行轨迹上逐组发送完整输入，组间排空两队列而不复位，每轮检查各 Yi 恰好新发布一次、结果符合 BigInt oracle、无残留到达集合。

总输入不超过 16 位时穷举；8×8 乘法覆盖 65,536 个输入对。更大域用显式 `--samples N`，加入边界、单比特和固定种子随机候选，去重后记录真实数量。重复发送、reset 和 JSON 重解析分别记覆盖计数；后者不是完整运行现场的续跑证明。输入全枚举也不是所有初始状态或所有事件交错的证明。

失败抛出 `error.report`，包含阶段、已完成覆盖数、错误及可获得的首个反例；尚未进入执行时反例为 null。CLI 以非零状态退出，可安全写报告时覆盖旧成功报告，避免留下虚假的通过记录。报告不能覆盖模型或规格的软/硬链接别名。

通用状态模型须有独立 next-state 和输出事件 oracle，并按需求覆盖重复同值、部分/交错输入、过滤而无输出、任务排队期间来源变化、自引用、下一组到达及非空队列恢复。要求“只更新变化的输出节点”时，另外断言每个输出节点的实际执行都改变其保存位。

优化审查和验证报告独立于模型，绑定最终 md5、format_md5 与规格/文件摘要，记录所用模板、候选、全部 EX 审查结论、数值和事件范围、节点数、状态位数、静态操作数、实际执行数与所测队列峰值。区分结构合法、功能通过、所声明范围内优化完成和全局最优；旧报告不能沿用于新模型。
