# JK节点网络模型的结构设计及构建规则

本工作区提供 [512 节点的 RGB 灰度循环复用模型](artifacts/rgb-gray-3x3-shared/README.md)：保存全部 216 位 RGB 输入后，用同一套核心依次计算九个灰度像素；完整循环结束后读取 72 位输出。[原 4,339 节点并行版](artifacts/rgb-gray-3x3/README.md) 保留为回归基线。

## JK 节点：

### JK 节点状态有两种：节点类型的判定依据：以 initial_q 为准

- 有状态节点：该节点始终存储一位 bit 数据 q = 0/1，q 会在模型初始化时被赋值且计算 ex 序列后写回 q 被更新
- 无状态节点：该节点不存储数据。只计算 ex 序列，完成后发布结果，不保存为下一次执行的起始状态。

### JK 节点有四种操作标识：
- `J0`: 置0
- `J1`: 保持
- `K0`: 保持
- `K1`: 翻转

### 操作标识会按顺序组合表达出 ex 计算序列在 JK 节点中：

#### 表达组合逻辑 ex：

- `Jx`: `q AND x`
- `Kx`: `q XOR x`
- `q = 0 = J0`
- `q = 1 = J0K1`
- `NAND(a,b) = J0K1J(a)J(b)K1`
- `NOR(a,b)  = J0K1K(a)J(b)K1K(a)`

- 只支持 J0、J1、K0、K1、J(X编号)、K(X编号)、J(Q编号)、K(Q编号)，按顺序拼接；允许忽略空白，不允许嵌套表达式，空表达式和未识别字符均报错。解析器必须消费完整字符串，不能只提取其中合法的片段继续计算。

#### ex 计算序列触发事件：
- 当前节点的任一`无状态节点的参数`到达时都先保存更新该节点对应的临时参数(覆盖最新值)（如有）。一次到达同时满足多处相同引用。所有临时参数都持续保留，直到到齐`触发执行`。
- 一次发布对同一目标只投递一次来源事件，同时满足多处引用；多条展示线不能额外增加执行次数，
- 当前节点的任一参数到达时都检测是否还有任一`无状态节点的参数`未到达，只有没有的时候才`触发执行` ex 计算序列求值。
- 当前节点没有`无状态节点的参数`每次参数事件都`触发执行` ex 计算序列求值，包括值未变化的事件，
- 当前节点只包含常量就只在初始化时执行
- ex 序列中无状态来源参数读取当前队列项保存的不可变副本；有状态来源参数在执行时读取其当前 q 值（沿线携带的值未必等于最终参与运算的值）。
- 无状态 JK 节点的 ex 必须以 J0 开头，否则标记异常并禁止执行。输入节点不受此限制。

#### 逻辑执行顺序 - `执行队列`

- `执行队列`中的节点都是`触发执行`且未执行的待执行节点，每执行完一个节点后就传递计算后的值到所有引用该值的节点，就会产生一批新的待执行节点按id编号大小排序后追加到队列尾，按队列顺序执行。
- 同一个节点如再次满足`触发执行`可以重复入队。同一节点重复触发时，保留多次执行即多次入队
- 节点入队后复制所有`无状态节点的参数`的到达值，且无法被修改，清空该节点保存的所有`无状态节点的参数`临时参数（如有）
- 当执行该节点时，才读取有状态节点 q 值（如有）
- 取出队首 → 读取参数并计算 → 写回有状态节点的 q → 向引用节点投递结果 → 将新触发项按节点编号数值排序追加到队尾。
- 单个队列项的计算、写回和结果投递不可被新输入打断；发送操作在两个队列项之间处理。
- 显示完整的`执行队列`列表及 当前队列长度
- 显示累计所有节点执行总次数。每个节点旁边显示该节点的执行次数。


### JK 网络模型
- description: 根据算术运算、位级布尔逻辑或状态转换需求，构建和优化自定义 JK 节点网络，并生成模型 JSON。采用本项目定义的顺序 J/K 运算规则，配置节点 ex、参数引用、初始状态及输出映射，并验证计算结果、状态更新和 FIFO 事件行为。适用于乘法、加法、按位逻辑及有状态计算需求。

#### 1.“根据算术、布尔逻辑或状态转换需求”
这里描述三类输入需求：
- 算术需求：例如两个整数相乘、相加，要求明确位宽、符号和输出规则。
- 布尔逻辑需求：例如对若干 bit 做 AND、XOR、取反、选择或条件判断。
- 状态转换需求：输出或下一状态依赖当前输入和已有状态。例如收到一个输入后翻转 q，或者根据输入更新并保存计算结果。
第三类尤其说明：这个 skill 的目标包含有记忆、会随事件更新状态的 JK 网络，不能仅用一次性的布尔函数概括。

#### 2.“生成自定义 JK 网络模型 JSON”
这是它的主要交付物：用 JSON 描述一个 JK 网络。
其中包括：
- nodes：有哪些 Q 节点，每个节点的 ex 是什么。
- initial_q：哪些节点有持久状态，以及初始值。
- q_y：输出 Y 映射到哪个 Q。
- spec 等附加字段：输入输出位宽、位序、使用协议和统计信息。
“自定义”指采用这个项目定义的 J/K 运算和事件规则。 JSON 中记录的是计算结构与初始状态；运行中的完整队列、到达缓存等并没有被保存进去。

#### 3.“适用于乘法器、加法器、位逻辑电路及 JK 结构优化”
这一段列举使用场景，但术语混用了两种表述体系。
**“乘法器、加法器”**结合当前实现，可以理解为“执行乘法或加法的 JK 网络”。代码通过部分积、全加器等构造方法生成节点和引用关系。为了与你的项目定位一致，写成“乘法、加法运算”更清楚。
**“位逻辑电路”**确实带入了电路设计的术语。结合实际产物，它在这里表达的是“由若干 bit 的逻辑运算组成的计算结构”，例如：
输入 X0、X1
→ JK 节点执行 J0K(X0)K(X1)
→ 发布 X0 XOR X1
但你的设计对象是具有顺序操作、状态和事件语义的 JK 节点网络。因此，这里用“位级布尔逻辑”或“按位逻辑运算”更准确，也不会让人误解为在生成硬件电路。
**“JK 结构优化”**指在满足需求和执行协议的前提下，调整节点表达式与引用关系，例如共享重复计算、删除无用节点、减少操作数量。它必须同时考虑触发行为：即使最终数值相同，删掉一个来源引用也可能改变节点何时执行、是否还能重复执行。

#### 4.“包含顺序 ex 编码”
意思是把节点的计算写成从左到右执行的 J/K 操作序列。
本项目规定：
Jx：q ← q AND x
Kx：q ← q XOR x
例如：
J0K(X0)J(X1)
依次表示“清零、与 X0 异或、与 X1 相与”，最终得到 X0 AND X1。
这里的顺序具有计算含义，不能把 ex 当作一组可以随意交换位置的操作。

#### 5.“FIFO 触发语义”
它同时规定两件事：什么时候可以执行，以及已触发的执行按什么顺序处理。
- 参数发布后，目标节点更新对应的到达缓存。
- 满足所需来源的到齐条件后，生成一个待执行项。
- 待执行项按先入先出的顺序执行。
- 执行后更新状态并发布结果，继续触发其他节点。
其中，无状态来源使用入队时保存的值；有状态来源在执行时读取当前 q。同值再次发布也可能触发执行。
所以它描述的是网络运行规则，不能仅凭表达式的数学结果判断整个网络正确。

#### 6.“和真值表验证”
对普通组合计算，这表示枚举输入，再将 JK 网络输出与独立数学结果比较。例如 8×8 无符号乘法共有 256 × 256 = 65,536 组输入。
但这个短语对整个 skill 的范围来说不够完整：
- 大输入域可能只能抽样，不能都称为完整真值表验证。
- 状态转换需要检查初始状态、输入序列、下一状态和输出。
- FIFO 网络还要检查重新发布、执行次数、队列和缓存。
因此，若要覆盖前文的“状态转换需求”，写成“功能、状态转换及事件行为验证”更准确。真值表只是其中一种验证方法。

#### 7.“不是传统 JK 触发器或神经网络权重生成”
这是为了避免两种概念混淆：
- 传统 JK 触发器：不能直接套用传统触发器的 J/K 输入规则来解释这里的顺序 ex。
- 神经网络权重生成：当前生成器构造的是节点、操作序列、引用关系和初始状态，没有生成或训练常规神经网络权重。运行中保存的 q 是状态值。
这句话限定当前 skill 的工作对象，并不证明 JK 网络与神经网络在表达能力或未来用途上存在什么绝对边界。


#### 模型包含三类节点标记：

- 输入节点 `X0..Xn`
- JK 节点 `Q0..Qn`
- 输出节点 `Y0..Yn`

- 工作区执行器还支持像素保存节点的可选 ID 后缀：`Q{全局编号}L{1–9}{R/G/B}{0–7}`，例如 `Q0L1R0`、`Q215L9B7`。`ex` 中的 Q 引用及输出映射使用完整 ID；排序先比较 Q 后的全局数字，再比较后缀。X、Y 仍采用纯数字编号。外部 ModelShow 及安装目录中的原版 skill 未自动更新，应使用模型目录提供的数值 ID 兼容版，或先扩展其解析器。

#### JSON 结构核心数据：

```json
{
  "name": "对当前 JK 模型的描述",
  "created_at": "2026-08-22T04:1787372535",
  "nodes": [
    {"id": "Q0", "ex": "J0K1J(X0)K1"},
    {"id": "Q1", "ex": "J0K1J(X1)K1"},
    {"id": "Q2", "ex": "J0K1J(Q0)J(Q1)K1"},
    {"id": "Q3", "ex": "J(X0)J(X2)K(Q0)"},
    {"id": "Q4", "ex": "J0K1J(Q2)K(X1)"},
    {"id": "Q5", "ex": "J(X3)J(Q1)K(Q3)"}
  ],
  "initial_q": {
    "0": [],
    "1": ["Q3", "Q5"]
  },
  "q_y": [
    {"Y0": "Q2"},
    {"Y1": "Q3"},
    {"Y2": "Q4"},
    {"Y3": "Q5"}
  ]
}
```

#### 参数含义：

- "name": "对当前 JK 模型的描述",
- "created_at": "2026-08-22T04:1787372535", // 创建时间戳
- "nodes": // JK 节点数据
- "initial_q": // 所有 有状态 JK 节点 的初始值
- "q_y":  // 所有输出节点映射到的 JK 节点

#### 视觉方案：
- 把每个像素的八个 bit 原样接入 JK，让 JK 跨位、跨像素计算局部特征，再把这些特征逐层组合。
```
位编号：     b7  b6  b5  b4  b3  b2  b1  b0
固定位值：  128  64  32  16   8   4   2   1
像素150：     1   0   0   1   0   1   1   0
```
- 3×3 RGB，每个颜色分量八位9×3×8＝216 bit
- 比较器 从低位向高位组合；当前位相同，就沿用低位比较结果；当前位不同，就由当前更高位决定结果。
```
差值需要 9 位有符号表示。例如：
100 − 80 = 20
80 − 100 = −20
```
- 局部特征可以有两种形式：
```
特征形式	示例	输出含义
布尔条件	R>L、中心是局部最大值	一个条件是否成立
多位数值	R−L、局部亮度和、对比幅度	一个有明确位序、范围的数值
```

- 一个节点输出一个 bit，并不限制一个特征只能输出一个 bit。 多个输出节点可以共同表达一个数值。
- 但“32 个独立布尔特征”和“4 个八位数值特征”虽然都占 32 个逻辑 bit，含义完全不同，后续计算不能混用。
- 可学习部分，负责决定观察哪些输入，以及怎样组合。
```
现在，每个 3×3 色度窗口提供 72 个候选输入 bit。可以给每个局部特征提取器规定一个有限的 JK 结构，然后学习：
- 引用哪个像素、哪个数位。
- 使用 J 还是 K。
- 引用哪些前面节点的结果。
- 哪些局部结果继续组合成输出。
```
- ?前面的训练方式仍然适用：用操作评分、来源评分辅助优化，再导出确定的 ex 和连接。变化在于，输入具有完整的八位数值信息。?
- 其中有两个可分别验证的设计：
```
- 从基本 J/K 操作学习。 允许模型从输入位中发现有用组合，搜索自由度较大。
- 提供已验证的比较、差分等基础模块。 让训练选择比较哪些位置、使用什么关系、怎样组合；基础数值关系由结构保证。
```
- 引入了人工选择的结构先验。它仍需通过训练确定哪些组合对任务有用。
- 优先验证比较、方向和差分等关系?
- “输入是否保留”、“JK 是否学到有效特征”、“后续聚合是否丢掉必要细节”等。
